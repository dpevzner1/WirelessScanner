Live Survey redesign: network explorer, spectrum, and saturation in one place

Three proposals for the next iteration. The mockups below are interactive and linked. Tick networks in the explorer: the spectrum recolours, the scope summary updates, and the saturation drawer shows what would be tested. Everything uses simulated networks.

Proposal A

Replace the card list with a grouped network explorer

Today the left panel is a single column of text cards. Each one repeats "SSID:", "CH", "RSSI" and "Qual" in the same orange, with a small checkbox and a separate SSID/AP mode switch. Scanning 30+ networks means reading every line.

Today

  • Flat list; every row has the same weight, so no scan path
  • Signal is a number buried in a text line; no visual meter or tier
  • A separate SSID/AP switch changes what a tick means
  • No search, sort, band filter, or count of what is selected
  • Selection colour is not linked to the graph

Proposed

  • Grouped by SSID with expandable BSSID rows. A tri-state checkbox on the group selects every AP of that network
  • Signal meter, value and tier label on every row, plus a 60-second sparkline
  • Chips for band, security and tier, plus "selected only"; search; sort by signal, name or channel
  • Identity swatch: a selected network gets the same colour here, on the spectrum, on tiles and in reports
  • Sticky footer states the resulting scope in plain words and holds the actions

Engine C-04/C-05: grouping related items (Gestalt), fewer simultaneous decisions (Hick's law, so chips sit in one row and details stay collapsed), visible system status (selection summary), and colour never as the only signal (tier labels).

Proposal B

Make the spectrum truthful, readable and focused

Today every AP is drawn as an identical parabola, coloured only by signal tier. Twenty networks therefore share three or four hues, labels collide, and a 20 MHz AP looks the same as an 80 MHz one.

Today

  • One colour per tier, so networks are indistinguishable from each other
  • Parabolas don't match real OFDM channels, which are flat-topped and as wide as the channel width
  • Overlapping labels in crowded channels; no hover detail
  • No view of congestion, DFS channels or 6 GHz

Proposed

  • Focus and context: up to 3 focused networks in full identity colour with labels; all others drawn as quiet outlines
  • Width-true channel masks (20/40/80/160 MHz, flat top, sloped skirts)
  • Signal bands −67/−70/−80 dBm, the same bands as the saturation charts
  • Congestion strip under the axis, with a "least busy" channel marker; DFS shading; band tabs 2.4 / 5 / 6 GHz
  • Hover tooltip, plus a waterfall view (channel × time) for spotting intermittent interference

Colour rule (validated): the 8-colour identity palette passes all checks for adjacent pairs on the app's black. With overlapping shapes (every pair can touch), only the first 3 colours stay distinguishable for colour-blind viewers. So: at most 3 focused networks, always direct-labelled, plus hover. Networks selected after the first three stay as outlines (still selected and captured) until a coloured one is unticked, so colours never jump between networks.

Proposal C

Move the saturation test into Live Survey, driven by the same selection

Today the saturation tab has its own adapter picker, its own DISCOVER scan, its own scope menu and its own table of networks. The same networks are selected twice, with different rules. One selection should drive everything: what you see, what you capture, and what you test.

SelectTick SSIDs or individual APs in the explorer. The footer states the scope in words.

RunThe spectrum area gains a Test view with tiles and a timeline. Explorer rows show live badges: NOT SEEN, DROP, CH CHANGE.
ReviewResults open in the same drawer; reports export from there. Past tests join capture sessions in History.

What changes in the app

  • The SATURATION TEST tab is removed; its setup becomes the Live Survey drawer, and its history joins HISTORY / LOGS
  • The DISCOVER step disappears: Live Survey is always scanning
  • The SSID/AP mode switch disappears: the tree replaces it
  • Capture sessions and saturation tests share the selection, the adapter and the scan loop
  • While a test runs, the selection is locked (read-only) so the scope can't drift; markers stay available

What stays the same

  • The analytics (SAT-ANALYTICS-1), storage, reports, geolocation and REST API
  • Fresh-scan rules and STALE/FAILED handling
  • The amber-on-obsidian look of the app chrome. Data colour is the only new colour system

Found while preparing this: concurrent scans clash

Live Survey (MainWindowViewModel), the saturation runner and DISCOVER each call ScanAsync on the same adapter instance. The adapter keeps one pending-scan slot per interface, so a second concurrent call replaces the first, and the first waits out its 6-second timeout and is recorded as STALE. A saturation test running while Live Survey scans can therefore lose fresh cycles in the app. The 15-minute hardware run used its own adapter instance, so it didn't hit this. Proposal C fixes it structurally with one scan scheduler that every view subscribes to. This would be logged as finding F18 before any change.

Q2

Allow "Mixed" scope (SSID groups plus single APs in one test)? It needs a small analytics-neutral change to how targets are tracked.

Q3

Focus limit of 3 coloured networks on the spectrum (validated for colour-blind readers), with the rest as outlines? Or allow up to 8 with mandatory labels and hover?

Q4

Waterfall view now or later? It needs per-scan history kept in memory for the live view (about 60 scans × channels).

Q5

Fix F18 first as a standalone change (shared scan scheduler), even if the redesign is scheduled later? It is a data-quality bug.
