# Decision DR-0002: Main folder is canonical; `GitHub Export/` is a generated mirror

Status: approved  
Date: 2026-10-15  
Owners: demitri.pevzner; Claude Code (implementer)  
Supersedes: none

## Context
- The source exists twice: in the main folder and in `GitHub Export/` (a git clone of `github.com/dpevzner1/WirelessScanner`, HEAD `9e10314`).
- The two copies had already drifted: Setup and the installer scripts exist only in the main folder; README and `.slnx` differ (finding F08).
- The owner directed: "main folder for the actual project content and files, but the GitHub is the github repository readiness folder, simply sync those two, and ensure that the documentation is kept up to date."

## Decision
- **Canonical authority:** the main folder.
- **Derived projection:** `GitHub Export/` is produced by `tools/sync_github_export.py`. The script mirrors an explicit allow-list of source, documentation and governance paths and removes mirrored files that no longer exist in the canonical folder. It never touches `.git/`, and it never copies:
  - build output (`bin/`, `obj/`, `publish/`);
  - local data (`*.db`), logs, API keys (`API/`, `api_key.*`);
  - `node_modules/`.
- **Installer:** `GitHub Export/EXE INSTALLER/` is generated by `pack_installer.py` and synced like everything else.
- **Publication:** the sync never commits or pushes. Committing and pushing are separate, owner-approved steps.
- **Validation:** `sync_github_export.py --check` exits non-zero when the mirror differs. Checkpoint 9 in `PROJECT_CONVENTIONS.md` requires a clean check before a change is considered finished.

## Alternatives

### Make `GitHub Export/` canonical and delete the duplicate
Rejected: the owner explicitly wants the main folder canonical.

### Turn the main folder into the git repository
Not chosen: the owner wants a separate readiness folder. It can be revisited later through a new decision.

## Consequences
- Benefits: one place to edit; the mirror is reproducible; drift is detectable.
- Costs and obligations:
  - every change ends with a sync and a clean `--check`;
  - new top-level paths must be added to the allow-list deliberately, which prevents accidentally publishing secrets.

## Exit and rollback criteria
- Success gate: `--check` reports 0 differences after a sync, and `git status` in the mirror shows only the intended changes.
- Stop condition: the sync would delete anything under `.git/` or `EXE INSTALLER/` that has no canonical counterpart. Investigate before running it.
- Rollback: `git checkout -- .` inside the mirror restores the last committed state.
